# Mythic Key

Корень рабочей копии — папка с `AGENTS.md` (родитель `igor-main/`). Скилл лежит в `.grok/skills/mythic-key/`.

Клон GitHub `pidrpen/igor`: в корне уже содержимое `igor-main/` плюс этот `AGENTS.md` и `.grok/`. Префикс `igor-main/` в путях отбросить.

## Новая сессия

Не обходить весь репозиторий и не писать заново большой разбор.

1. Этот файл (дерево + перелив).
2. `references/карта.md` — куда какой файл, что только в Тесте, что уже в основе.
3. `igor-main/Тест/SESSION.md` — что сейчас актуально.
4. По задаче, не всё сразу:
   - баланс / «напомни» / жёлтое → `igor-main/Тест/СЕССИЯ_разбор_баланса.md` + `бэклог_ветки.md`
   - прокачка → `igor-main/прокачка/КОНЦЕПТ.md` (не пилить без прямой просьбы)
   - правка кода → только файлы из карты под эту правку
   - арт / спрайт / анимация скилла → `references/генерация.md`

`Копия не трогать/`, `game-parts/`, вложенный старый Тест внутри копии — не читать.

Добавил, перенёс или переименовал файл / дом фичи — в **том же ходе** поправь `references/карта.md`. Не копируй туда журнал сессии и не дублируй жёлтые решения.

## Дерево

- `igor-main/Тест/` — рабочая копия. Сюда идут обычные правки игры.
- `igor-main/` кроме `Тест/` — основа. Спит, пока пользователь не сказал «перелив» / «перенести на основу».
- `igor-main/прокачка/` — песочница 1–40, основа и Тест не импортируют. Не мешать с жёлтым разбором.
- `igor-main/Копия не трогать/` — не редактировать.
- «на основе и на тесте» — править оба дерева одним и тем же поведением.

Отложенные идеи: `igor-main/Тест/бэклог_ветки.md`.  
Разбор баланса: `igor-main/Тест/СЕССИЯ_разбор_баланса.md`.

## Обычная работа

Править только `igor-main/Тест/`, пока не сказано переносить.

После правок JS/CSS — бамп `?v=` у затронутых тегов в том `index.html`, который менялся.

Жёлтые решения из разбора баланса в код **не вшивать сами** — только если пользователь попросил вшить названный пункт.

В ответах пользователю без сокращений имён способностей (не «суд», а Правосудие). Слово «глагол» не использовать. Без смайликов.

**Единицы всегда подписывать.** Рядом с числом писать, в чём оно: «т» (atk × вес / 15, уже после атаки спека), HP, %, ходы, заряды, очки серии, ярость / мана / энергия / Энергия Света / сила рун / пар / детали. Голое «800», «2.6», «2700» без единицы не писать. Если это отношение (индекс танка, «5 / СТ»), сказать что это отношение, не тысячи.

## Перелив

Только если пользователь сказал «перелив» / «перенести на основу» (или оба дерева) и назвал кусок. Не копировать всю папку `Тест/`.

Перелив — копия названного куска, не «починить заодно» и не менять управление. Если после переноса что-то сломалось — чинить поломку, не придумывать новый способ играть. Про лишние правки сначала сказать и подождать.

### Что назвать куском

- **Класс** (по умолчанию): `class-balance/<класс>-abilities.js`. `apply()` подменяет весь класс. Копия файла = все спеки этого класса.
- **Один спек:** в файле основы заменить только объект `specs[]` с этим `id`. Соседние спеки основы не трогать. Вместе со спеком, если менялось именно оно: пассивки / `MASTERY_BY_SPEC` с ключом этого спека.
- **Фича** (рейд, ауры у портретов, фон лобби): список файлов + крючки, не «весь js/».

Новый класс (инженер): файл пакета + тег `<script>` в `index.html` основы.

### Как копировать

1. Снять, чем тест отличается от основы по названному куску. Не тащить соседей.
2. Не подменять файл основы целиком, если в тесте в нём ещё магазин, тестовая комната, читер, инженер или бейджи «Тест».
3. Новые файлы на основе — только кусок: `js/raid.js`, `js/dungeon-inst.js`, `js/raid-catacombs.js`, `css/raid.css`, названные ассеты. Стили рейда/аур/катакомб/сплита/флангов на основе живут в `css/raid.css`, не в `test-room.css`.
4. В общие файлы (`ui.js`, `combat-loop.js`, `combat-flow.js`, `save.js`, `enemies.js`, `combat-ui.js`) вшивать крючки. Не выкидывать из основы привал, таланты, старый клик по карточкам.
5. `living('enemy')` может прятать `vaultAway` только в рейде. В ключе враги без этого флага должны жить как раньше.
6. `combat-ui.js` не копировать оптом: слить нужный UI. Бой остаётся: способность (или 1–9) → клик по портрету цели. Автоудар / автоцель не добавлять. Если клик по карточке не доходит — чинить привязку клика (`unit` / `unit-stack` / делегирование на ряд), не убирать выбор цели.
7. Скрытие лобби-интерфейса: не `display: none` на карточках (ломает высоту и скролл). Карточки `opacity: 0`, затемнение фона — отдельный слой с плавным `opacity`.
8. При правке `index.html` теги `<script>` закрывать полностью (`</script>`). Оборванный тег глотает следующие файлы (`dealDmg is not defined` и т.п.).
9. После копирования JS/CSS — бамп `?v=` в `index.html` основы (и теста, если его тоже трогали).
10. Строка в `igor-main/Тест/SESSION.md`: что уехало, что осталось. Если дом фичи сдвинулся — строка в `references/карта.md`.

### В перелив не класть, пока не назвали

- `js/test-room/`, `assets/sprites/`
- `js/shop/`
- `class-balance/cheat-abilities.js` (инженер уже в основе)
- бейджи `TEST_SPECS` / пометки «тест» на спеках
- Excel, `задачи_мне.txt`, предложения ИИ
- `прокачка/`

В перелив **класса** не класть рейд, магазин, комнату анимаций.

### После перелива

- Синтаксис затронутых JS.
- Ключ 5: способность, потом клик по цели; урон/хил проходит, ход уходит. Не проверять «кнопка сразу бьёт сама».
- Если кусок — рейд: то же в рейде 10.
- Если пользователь сказал «на основе и на тесте» — то же поведение в обоих деревьях.
